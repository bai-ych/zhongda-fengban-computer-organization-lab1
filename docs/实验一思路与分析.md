# 实验一思路与分析

## 1. 实验目标和边界

实验一不是重新设计一个 CPU，而是读懂模板提供的模块接口，并补齐单周期 RV32I 数据通路中的控制和连线。正确实现后，应同时满足：

- 基础 RV32I 程序可以执行。
- load 和 store 能正确访问内存。
- 分支和跳转能正确更新 PC。
- CPU 测试可以读取期望的寄存器和内存结果。
- ChiselTest 能生成 VCD，供 GTKWave 观察。

实验一包含基础整数指令、通用寄存器、load/store、分支、jal/jalr 和波形仿真；不包含 CSR、中断、异常、流水线冒险、缓存和乘除法扩展。

## 2. 先读接口，再写实现

实现前先看五个模块：

1. InstructionFetch：输入跳转信息和指令存储器数据，输出 PC 和当前指令。
2. InstructionDecode：输入指令，输出寄存器地址、立即数和控制信号。
3. Execute：输入寄存器数据、立即数和 PC，输出 ALU 结果与跳转信息。
4. MemoryAccess：把 ALU 结果解释为内存地址，处理字节、半字和字访问。
5. WriteBack：在 ALU 结果、内存读数据和 PC 加 4 之间选择写回值。

CPU 顶层的任务是让这些接口首尾相接，而不是复制 lab2 的全部代码。

数据流可以概括为：

取指和 PC -> 译码和寄存器读 -> ALU 执行 -> 内存访问 -> 写回寄存器
                                      |
                                      +-> 跳转地址回到取指

判断一个信号怎么连时，应追踪它的生产者和消费者。例如 Execute 的 reg1_data 生产者是 RegisterFile，消费者是 ALU；InstructionDecode 的 ex_immediate 消费者是 Execute。

## 3. 四个标记区的推导

### 3.1 取指：跳转优先，否则 PC 加 4

当前周期已经取出的指令不能因为跳转而丢弃，跳转影响的是下一个周期的 PC。因此逻辑是：

- instruction_valid = 1 且 jump_flag = 1：PC_next = jump_address。
- instruction_valid = 1 且 jump_flag = 0：PC_next = PC + 4。
- instruction_valid = 0：PC 保持不变。

PC 是 RegInit，instruction_address 输出当前 PC。无效取指时送 NOP，避免加载阶段把无效数据当作真实指令执行。

### 3.2 译码：使用最小控制表

| 指令类别 | ALU op2 | 读内存 | 写内存 | 写回来源 |
|---|---|---:|---:|---|
| R 型 | rs2 | 0 | 0 | ALU |
| I 型 | immediate | 0 | 0 | ALU |
| load | immediate | 1 | 0 | memory |
| store | immediate | 0 | 1 | 不写回 |
| jal/jalr | immediate | 0 | 0 | PC+4 |
| 其他基础指令 | immediate | 0 | 0 | ALU |

ALU op1 的特殊情况由模板给出：auipc、分支和 jal 使用指令地址，普通运算使用寄存器。

默认值必须覆盖所有 opcode。组合逻辑输出只在部分分支赋值，会触发 FIRRTL 初始化错误。

### 3.3 执行：控制信号决定多路选择器

执行级可以拆成三件事：

1. ALUControl 把指令字段翻译为 ALUFunctions。
2. op1 在寄存器 1 和 PC 之间选择。
3. op2 在寄存器 2 和立即数之间选择。

例子：

- addi x1, x2, 5：op1 = regs[x2]，op2 = 5，ALU = add。
- add x1, x2, x3：op1 = regs[x2]，op2 = regs[x3]，ALU = add。
- sw x2, 8(x3)：op1 = regs[x3]，op2 = 8，ALU = add。
- auipc x1, imm：op1 = PC，op2 = imm，ALU = add。

### 3.4 顶层：按照数据流连接

顶层连接检查顺序：

1. 取指输出连接到译码输入。
2. 译码读地址连接到寄存器堆读地址。
3. 寄存器堆读数据和译码立即数连接到 Execute。
4. Execute 结果连接到访存地址和写回 ALU 输入。
5. 内存读数据连接到写回内存输入。
6. 写回输出连接到寄存器堆写数据。
7. Execute 跳转输出回接取指级。

如果 FIRRTL 报 RefNotInitializedException，应沿这条数据流检查：上游是否没有赋值，或者顶层是否漏连。

## 4. 以 sb.asmbin 为例的执行分析

ByteAccessTest 同时覆盖算术、地址计算、字节存储、字节加载和写回，适合用于理解实验一。

执行过程：

1. 程序构造待写入的字节数据和目标地址。
2. sb 被译码为 S 型指令，立即数来自 instruction(31,25) 和 instruction(11,7) 的拼接。
3. Execute 计算 rs1 + immediate，得到内存地址。
4. InstructionDecode 使 memory_write_enable 有效，MemoryAccess 根据 funct3 = 000 只打开目标字节的 write strobe。
5. 后续 lb 或 lbu 使用同一个地址计算路径读出字节；MemoryAccess 根据地址低位选择内存数据中的字节，并进行符号扩展或零扩展。
6. WriteBack 把内存读数据选择为寄存器写回值。
7. 测试通过调试端口读取寄存器并比较结果。

测试期望：

- x5 = 0xDEADBEEF
- x6 = 0x000000EF
- x1 = 0x000015EF

这些结果同时检查字节位置、端序、符号扩展和寄存器写回。

## 5. 验证策略

### 5.1 分层验证

建议按以下顺序：

1. 先运行 InstructionDecoderTest、InstructionFetchTest、RegisterFileTest 等局部测试。
2. 再运行 ByteAccessTest，它能快速暴露取指、译码、ALU、访存和写回问题。
3. 最后运行 FibonacciTest 和 QuicksortTest，检查分支、跳转、递归和大量内存访问。
4. 测试通过后打开 VCD，对照 PC、当前指令和内存写使能观察时序。

### 5.2 波形观察重点

打开 TestTopModule.vcd 后，建议观察：

- instruction_address 是否按 4 增加；
- 分支或跳转成立时 PC 是否到达目标地址；
- memory_bundle.address 是否等于 ALU 地址结果；
- write_enable 和 write_strobe 是否只在 store 时有效；
- load 时内存数据是否进入写回路径；
- debug_read_address 改变后，debug_read_data 是否对应目标寄存器。

波形中看到某信号为 0 不一定是错误，要结合当前指令判断。普通算术指令的内存写使能应该为 0，load 指令的 ALU 结果应该是地址，而不是最终加载数据。

### 5.3 常见现象与定位

| 现象 | 优先检查 |
|---|---|
| FIRRTL RefNotInitializedException | 四个实验标记区是否漏赋值，CPU 顶层是否漏连 |
| PC 一直为 0 | instruction_valid、取指级 PC 更新、CPU 时钟 |
| 所有寄存器都为 0 | CPU 到 Execute 的连线、程序 ROM 是否加载、仿真器是否启动 |
| 地址正确但数据错误 | funct3、地址低位、write strobe、端序 |
| 跳转后跑飞 | B/J immediate、if_jump_address、PC 更新优先级 |
| 没有 VCD | WriteVcdAnnotation、测试是否实际运行、test_run_dir |
| 找不到 verilated.mk | 项目和 Verilator 放到纯英文路径 |
| WData 或 native harness 错误 | ChiselTest 和 Verilator 版本不匹配 |

## 6. 可迁移性边界

本实现遵循 YatCPU 已有模块接口和 Parameters，适合在同一工程、同一 Chisel/ChiselTest 版本中作为参照。它不能保证直接适配任意其他人的 CPU，因为其他项目可能改变：

- 数据宽度、地址宽度或寄存器数量；
- Bundle 字段名称和方向；
- 内存接口的字节使能定义；
- PC 初始地址；
- Chisel、FIRRTL、ChiselTest 或 Verilator 版本。

迁移时先对照接口和参数，再移植控制逻辑；不要只复制四个文件的文本。
