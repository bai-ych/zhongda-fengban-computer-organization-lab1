# 实验一学习路线

## 一、先建立整体认识

实验一不是从零写完整 CPU，而是在已有的单周期 RV32I CPU 框架中补齐四个实验标记区。先把 CPU 看成一条数据通路：

```text
PC/取指 -> 指令译码和寄存器读取 -> ALU 执行 -> 访存 -> 写回寄存器
   ^                                                   |
   +------------------- 跳转目标地址 ------------------+
```

每次遇到一个信号，都问三个问题：

1. 这个信号由谁产生？
2. 它被谁使用？
3. 它在当前指令类别下应该是什么值？

这三个问题比直接照抄代码更重要，因为后续实验会增加 CSR、中断、流水线或外设接口。

## 二、按四个实验标记区学习

### 1. InstructionFetch：先解决 PC

理解 `RegInit`、时钟和 `when/otherwise`。有效取指时，普通指令让 PC 加 4，跳转指令让 PC 变为目标地址；无效取指时 PC 保持不变。

### 2. InstructionDecode：把指令变成控制信号

从 `opcode` 判断指令类别：R 型使用两个寄存器，I 型、load 和 store 使用立即数；load 打开读使能，store 打开写使能；load 写回内存数据，jal/jalr 写回 PC+4。

这里必须保证每个组合逻辑输出都有默认值，否则 FIRRTL 会报 `RefNotInitializedException`。

### 3. Execute：让 ALU 得到正确输入

ALU 第一个操作数可能来自寄存器或 PC，第二个操作数可能来自寄存器或立即数。`ALUControl` 负责根据指令字段选择加、减、比较、移位等具体运算。

### 4. CPU：沿数据流连接模块

顶层连接的核心顺序是：取指连接译码，译码连接寄存器堆，寄存器堆和立即数连接执行，执行连接访存和写回，跳转结果回到取指。

## 三、最后再看测试和波形

先做局部测试，再做 CPU 测试：

1. `InstructionFetchTest`：检查 PC 和指令获取；
2. `InstructionDecoderTest`：检查控制信号；
3. `ExecuteTest`：检查 ALU 输入和执行结果；
4. `ByteAccessTest`：检查 sb/lb/lbu、地址计算、字节写使能和写回；
5. `FibonacciTest`、`QuicksortTest`：检查分支、跳转、递归和大量内存访问。

波形调试时不要只看一个信号。应把“当前指令—控制信号—ALU 地址—内存接口—写回结果”连起来看，才能判断错误发生在哪一级。

## 四、建议的学习记录方式

每次修改代码后记录四项：

- 修改了哪个模块和哪个输入输出；
- 这条指令的 opcode 和立即数格式是什么；
- 预期波形应该出现什么变化；
- 通过了哪些测试，失败时最早异常在哪个信号。

这样可以把一次实验变成可复用的调试方法，而不仅是一次性的代码填空。
