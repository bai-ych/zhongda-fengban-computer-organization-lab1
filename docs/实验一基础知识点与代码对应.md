# 实验一基础知识点与代码对应

## 1. 实验一要完成什么

实验一是在现有的单周期 RV32I CPU 框架中补齐四类连接：

1. 取指级：让 PC 在顺序执行和跳转之间正确更新。
2. 译码级：根据 opcode 产生 ALU 第二操作数、访存和写回选择信号。
3. 执行级：把寄存器、立即数和 PC 送入 ALU，并选择正确运算。
4. 顶层 CPU：把寄存器堆、译码、执行、访存和写回连成数据通路。

项目中的 lab1 标记区域就是实验一的填写区域。实验一不要求加入 lab2 才有的 CSR、中断和特权级逻辑。

## 2. 必须掌握的基础

### 2.1 Scala、sbt 和项目结构

- Scala 是本项目使用的语言；Chisel 是用 Scala 描述硬件的 DSL。
- build.sbt 定义 Scala、Chisel 和 ChiselTest 版本。本副本使用 Scala 2.13.10、Chisel 3.6.0、ChiselTest 0.6.0。
- src/main/scala 是硬件实现，src/test/scala 是测试，src/main/resources 是程序资源。
- test 不是普通的 main 函数，而是由 ScalaTest 和 ChiselTest 启动的硬件仿真。

### 2.2 Chisel 核心概念

| 概念 | 含义 | 本实验中的用法 |
|---|---|---|
| Module | 可综合硬件模块 | InstructionFetch、Execute、CPU |
| IO | 模块输入输出接口 | io.instruction、io.ex_immediate |
| UInt | 无符号硬件位向量 | PC、寄存器数据、地址 |
| Bool | 单比特信号 | 跳转、读使能、写使能 |
| RegInit | 带初值的时序寄存器 | 取指级 PC |
| := | 硬件连线/赋值 | 把上游输出连到下游输入 |
| when/otherwise | 条件硬件逻辑 | PC 更新 |
| Mux | 二选一多路选择器 | ALU 操作数选择 |
| MuxLookup | 根据编码查表 | 写回来源、立即数 |
| Module(new X) | 实例化子模块 | CPU 实例化各级 |

关键区别：Scala 代码是在生成硬件，而不是按照软件语句顺序直接执行。pc := pc + 4.U 描述的是时钟沿写入 PC 的逻辑。

### 2.3 RV32I 指令字段

32 位 RISC-V 指令常用字段为：

31..25 是 funct7，24..20 是 rs2，19..15 是 rs1，14..12 是 funct3，11..7 是 rd，6..0 是 opcode。

- opcode 决定指令大类。
- rs1 和 rs2 是寄存器读地址。
- rd 是寄存器写地址。
- funct3 和 funct7 用于区分同一大类中的具体操作。
- I、S、B、U、J 型立即数的拼接方式不同，框架已经在 InstructionDecode.scala 中准备好。

主要 opcode：

| 名称 | opcode | 作用 |
|---|---|---|
| RM | 0110011 | 两个寄存器参与 ALU 运算 |
| I | 0010011 | 寄存器和立即数参与 ALU 运算 |
| L | 0000011 | 计算地址并读取内存 |
| S | 0100011 | 计算地址并写入内存 |
| B | 1100011 | 条件分支 |
| jal | 1101111 | 直接跳转并写回下一条地址 |
| jalr | 1100111 | 间接跳转并写回下一条地址 |
| lui | 0110111 | 将 U 型立即数写入寄存器 |
| auipc | 0010111 | PC 加 U 型立即数 |

### 2.4 单周期 CPU 数据通路

每条指令在一个 CPU 周期内经过：

取指 -> 译码和读寄存器 -> ALU 执行 -> 访存 -> 写回寄存器

这些级在代码中拆成模块，但实验一不是流水线；它们在同一个 CPU 周期内组合连接，时钟沿主要更新 PC 和寄存器堆。

### 2.5 控制信号

- ex_aluop1_source：ALU 第一个输入选寄存器还是指令地址。
- ex_aluop2_source：ALU 第二个输入选寄存器还是立即数。
- memory_read_enable：当前指令是否是 load。
- memory_write_enable：当前指令是否是 store。
- wb_reg_write_source：写回数据来自 ALU、内存还是下一条指令地址。
- reg_write_enable：当前指令是否写通用寄存器，框架中已经给出。

最重要的控制规则：

- R 型：ALU = rs1 op rs2。
- I 型和 load：ALU = rs1 op immediate。
- S 型：ALU = rs1 + immediate，并写内存。
- load：ALU = rs1 + immediate，并读内存。
- auipc 和 jal：ALU 第一个输入使用 PC。
- jal 和 jalr：写回 PC + 4。

## 3. 知识点在代码中的对应

### 3.1 InstructionFetch.scala

文件路径：src/main/scala/riscv/core/InstructionFetch.scala

实现思想：

- instruction_valid 有效时接收指令。
- jump_flag_id 有效时，下一 PC 取 jump_address_id。
- 否则下一 PC 取当前 PC 加 4。
- instruction_valid 无效时 PC 保持不变，并送出 NOP。

当前指令用当前 PC 取出；跳转只影响下一个周期的 PC。这是理解单周期跳转的关键。

### 3.2 InstructionDecode.scala

文件路径：src/main/scala/riscv/core/InstructionDecode.scala

实验一需要实现：

- RM 指令的 ALU 第二输入选择寄存器。
- 其他基础指令的 ALU 第二输入选择立即数。
- L 指令打开 memory_read_enable。
- S 指令打开 memory_write_enable。
- L 写回内存数据。
- jal 和 jalr 写回 PC 加 4。
- 其他未匹配指令默认写回 ALU 结果。

默认值非常重要。组合逻辑的每一个输出都必须在所有输入情况下有定义，否则 FIRRTL 会报告 RefNotInitializedException。

### 3.3 Execute.scala

文件路径：src/main/scala/riscv/core/Execute.scala

执行级做三件事：

1. ALUControl 根据 opcode、funct3、funct7 生成 ALUFunctions。
2. ALU 第一个操作数在寄存器 1 和指令地址之间选择。
3. ALU 第二个操作数在寄存器 2 和立即数之间选择。

典型例子：

- addi：op1 是 regs[rs1]，op2 是立即数。
- add：op1 是 regs[rs1]，op2 是 regs[rs2]。
- sw：op1 是 regs[rs1]，op2 是存储偏移立即数。
- auipc：op1 是 PC，op2 是 U 型立即数。

### 3.4 CPU.scala

文件路径：src/main/scala/riscv/core/CPU.scala

顶层需要把以下信号送给 Execute：

- 取指得到的 instruction。
- 取指得到的 instruction_address。
- RegisterFile 的 read_data1 和 read_data2。
- InstructionDecode 的 ex_immediate。
- InstructionDecode 的 ex_aluop1_source 和 ex_aluop2_source。

其余访存和写回连线在模板中已经存在。CPU 顶层的原则是沿数据流连接：取指到译码，译码和寄存器堆到执行，执行到访存和写回，写回回到寄存器堆，跳转回到取指。

## 4. 测试和波形

测试文件：src/test/scala/riscv/singlecycle/CPUTest.scala

- FibonacciTest：检查递归程序结果。
- QuicksortTest：检查排序结果。
- ByteAccessTest：运行 sb.asmbin，检查字节存取和寄存器结果。

poke 是给硬件输入赋值，peek 或 expect 是读取并检查硬件输出，clock.step 是推进仿真时钟。

TestAnnotations.scala 默认使用 VerilatorBackendAnnotation 和 WriteVcdAnnotation，因此测试应生成 TestTopModule.vcd。用 GTKWave 打开 VCD 后，先展开顶层模块，再加入 clock、instruction_address、内存接口和寄存器调试信号。

## 5. Windows 注意事项

1. 项目建议放在纯英文路径，例如 D:/yatcpu-lab1-reference。Scala、Chisel、Treadle 和 Make 在中文路径下容易出现编码或相对路径问题。
2. Java 使用 JDK 17；sbt 和 Scala 版本由 build.sbt 与 IDEA 导入配置决定。
3. ChiselTest 0.6.0 与 Verilator 版本存在接口兼容性要求。课程项目年代对应 Verilator 4.x；较新的 Verilator 5.x 可能出现 WData、运行时接口或 native harness 问题。
4. 不能只看 Scala 编译成功；至少要跑一个完整测试，并确认 VCD 文件生成且时间轴增长。
5. Treadle 可以用于局部组合逻辑检查，但本项目的同步存储器和多时钟测试应以 Verilator 结果为最终依据。
